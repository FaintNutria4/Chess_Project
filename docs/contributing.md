# Contributing / Conventions

## Code style

- **No comments in code** (C++ and GDScript) unless explicitly requested. Prefer clear names; explain non-obvious intent in docs instead.
- Terse, direct style. Avoid speculative abstractions.
- **C++17** everywhere (`/std:c++17`, plus `/EHsc` on MSVC — already set in both `SConstruct` files).
- Explicit `operator==` / `operator!=` on domain structs (C++17; defaulted comparisons would need C++20).
- GDScript: typed declarations where practical (`:=`, `-> void`), tabs for indentation (see `.editorconfig`).
- Include guards in headers (`#ifndef CHESS_*_HPP`), `#include` own header first in `.cpp`.

## Where does new logic go?

Decision table — apply in order:

| Question | Layer | Location |
|---|---|---|
| Does it decide chess legality, state, or notation? | Domain | `core/domain/` |
| Does it translate Godot types ↔ domain types? | Interop | `client/src/interop/` |
| Is it a GDScript-callable game operation? | Facade | `client/src/chess_game.*` |
| Does it decide how something looks or reacts to input? | Presentation | `client/scenes/` |
| Does it hold cross-scene session state? | Autoload | `client/autoload/` |

Hard rules:

1. `core/domain/` never includes `godot_cpp/*` or Godot headers.
2. GDScript never implements rules (no move generation, no check detection, no FEN parsing in scripts).
3. Only `board.gd` and autoloads instantiate/call `ChessGame`; everyone else uses signals or goes through `board.gd`.
4. All `Variant` ↔ domain conversions belong in `interop/convert.*`.
5. Children emit signals upward; parents call methods downward.

## Testing

- **Domain changes → run core tests first.**

  ```powershell
  cd core
  scons
  .\tests\chess_core_tests.exe     # must end with: 30 checks, 0 failures
  ```

- Tests are plain C++ (`core/tests/test_rules.cpp`), no framework. Use the `CHECK` macro; wrap brace-initializers in extra parentheses: `CHECK((sq == Square{1, 2}))`.
- If you add checks, the expected total in docs (`README.md`, `AGENTS.md`, `core-api.md`) changes — update it.
- There is no automated GDScript test harness yet; verify scene behavior manually in the editor (F5): click piece → highlights → move → HUD updates.

## Build

```powershell
# Extension (from client/)
scons platform=windows target=template_debug arch=x86_64 api_version=4.7
scons platform=windows target=template_release arch=x86_64 api_version=4.7
```

- `api_version=4.7` is mandatory (godot-cpp master @ 507ed9d has no `godot-4.7` tag).
- If `scons` is missing from an agent shell, call it by full path: `& "C:\Users\Alvaro\AppData\Roaming\Python\Python311\Scripts\scons.exe" <args>`.
- After C++ edits, regenerate the clangd DB so editors see both `client/` and `core/` files:

  ```powershell
  scons platform=windows target=template_debug arch=x86_64 api_version=4.7 compiledb=yes compiledb_file=../compile_commands.json
  ```

  Then restart the clangd language server. The database lives at the **repo root** (`compile_commands.json`), deliberately, so it covers `core/` sources too.

- DLLs hot-reload when the Godot editor window regains focus.

## Build artifacts

- SCons drops `.obj` files next to sources (e.g. `core/domain/*.obj`, `client/src/*.obj`) and `.sconsign.dblite` in each build root — do not commit them; they are regenerated.
- `client/bin/*.dll`, `client/.godot/`, `client/.cache/` are generated.
- `compile_commands.json` (root and `client/`) is generated by `compiledb=yes`.
- `client/godot-cpp/` is vendored — do not edit it directly.

## Documentation

- Humans: `README.md` + `docs/*.md`.
- AI models: `AGENTS.md` (invariants, file map, commands, gotchas) with pointers into `docs/`.
- When a contract changes (Dictionary keys, signals, method signatures), update **both** the docs and the consumers in the same change: `docs/facade-api.md` ↔ `chess_game.*` ↔ `board.gd`/`main.gd`; `docs/core-api.md` ↔ `core/domain/*`; `docs/scenes.md` ↔ scene scripts.

## Scene/GDScript pitfalls

- `const` only accepts compile-time literals — constructors (`PackedVector2Array(...)`, `Color(...)`) go in `var` (see `piece.gd` `SHAPES`).
- Flat-argument `PackedVector2Array(a, b, ...)` is `.tscn` syntax only; GDScript needs `PackedVector2Array([Vector2(a, b), ...])`.
- Instantiated scene scripts assume child node paths (`$Base`, `$Visual`, `$StatusLabel`); if you rename nodes in the editor, update the script in the same change.

## Current scope boundaries

- Promotion through the UI is always queen (facade builds default `Move`).
- `server/` is intentionally empty; protocol work will reuse FEN from `core/`.
- Network autoload methods are stubs — do not treat them as working.
- Leftover editor templates (`client/node_2d.*`, `client/src/test.gd`, `client/src/node_2d.tscn`) are dead files, safe to ignore or delete when noticed.
